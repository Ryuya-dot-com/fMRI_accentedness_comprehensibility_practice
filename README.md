# ジョイスティックによる評定の練習

スキャナー外のTrainer（OTR-JOY-5など）を使う5段階評定課題です。2026-11-17、提供されたPre-ratingに基づき、各課題を説明2試行＋単独練習5試行へ変更しました。回答・操作ログは保存・送信せず、localStorage、IndexedDB、Cookie、アクセス解析は使用しません。

## 課題別リンク

- [理解しやすさの練習](https://ryuya-dot-com.github.io/fMRI_accentedness_comprehensibility_practice/?task=comprehensibility)
- [外国語訛りの練習](https://ryuya-dot-com.github.io/fMRI_accentedness_comprehensibility_practice/?task=accentedness)

1セッションでは1課題だけ実施し、終了後に別課題へ自動で進みません。課題指定のないURLでは2つのリンクから課題を選びます。以前の両課題連続実施は終了しました。本番の課題順に従い、該当する課題の前に説明と練習を行います。

## 実施方法

1. 研究室PCにTrainerとヘッドフォンを接続します。HTTPSとGamepad APIに対応したPCブラウザーで、その課題のリンクを開きます。
2. **本撮像と同じ参加者ID**を入力します。尺度の左右方向をMRIと同じ8条件周期で選び、条件決定後に入力欄を消去します。IDと氏名は保存・送信しません。
3. 中央で人差し指ボタンを押して離し、左端・中央・右端・中央の順に機器を確認します。軸・左右・ボタンは実際の操作から校正し、このページを開いている間だけ保持します。MRI用932のB2をTrainerのボタン番号へ流用しません。
4. 課題の説明を読み、最初の2音声を実験者の説明用として評定します。2音声目の評定・ITI後に「ここからはヘッドセットをして練習に取り組んでください」と表示し、時間制限なしで待ちます。
5. 装着後、中央で人差し指ボタンを新たに押すと、単独練習の5試行を開始します。説明で聞いた低・高の2録音も再提示します。
6. 「練習は終了しました。」で終了です。「もう一度練習する」で同じ課題を最初からやり直せます。Esc、機器切断、画面切替、音声停止では、その回を停止します。

## 操作・定義とMRIとの対応

- 最初の選択位置は3です。左右に動かさず、人差し指ボタンの新たな押下で3を確定できます。
- 中央から左右へ倒すたびに1段階移動します。倒したままでは連続移動しません。1・5へは、一度倒す→中央へ戻す→同じ方向へ再度倒す、の順です。
- 中央範囲±0.15、移動閾値±0.5、確定には新たな押下が必要、という処理はMRIと共通です。聴取中の操作、評定開始時の倒しっぱなし・押しっぱなしを回答へ持ち越しません。
- 評定画面の受付は3秒です。確定後は選択を緑色にし、3秒が終わるまで表示します。操作も確定もない試行を3として扱わず、未回答の案内を表示します。回答の正誤判定はしません。
- 指示はMRIの現行日本語定義から抽出します。Compは内容理解の正誤よりも理解の難しさの感覚、Accは日本語母語話者に近い発音かを尋ねます。今回のユーザー指示で「文法や語彙」の文を削除しました。2つの評価が一致する必要はないという説明は維持します。`instruction_version=prerating_ja_v4`。
- 端点は「理解しにくい／理解しやすい」「訛りが強い／訛りがない」です。IDによるX/Y反転を維持するため、下表の低・高は全参加者に共通の数字の正解ではありません。Xでは低側が1、高側が5、Yでは逆です。

本番288録音との同一録音・文IDの重複がないこと、Web用WAVがMRIのprepared音声とバイト単位で一致することを検証します。音声の文面、話者情報、Pre-ratingは参加者画面に表示しません。書き起こし課題Intelligibilityの共通アンカー10本と、Pythonの旧practiceフォームは今回変更していません。今回の練習は上のWebリンクを使用してください。

各音声の評定前待機0–2.5秒・ITI 2–6秒は、既存Python練習フォームから引き継ぎます。8固定フォーム、冒頭・末尾の固視各10秒を維持します。Webの選定順はMRI本番のID全体をseedにする疑似ランダマイズとは別です。練習に本撮像の540秒待機はありません。

## MRI内の音量確認

MRIの `audio_check` は、Speaker 5（RIT_M03_JP_B1_093）のprepared WAVを繰り返し使います。Webでは `audio/practice_06.wav` と同一の録音です。本番刺激と同じ正規化工程を通し、保存済みの測定値は−30.03 LUFS、ソフトウェア音量係数は両方0.3です。音声中の表示、3段階の音量回答、2回連続「ちょうどよい」で終了・最大15試行はMRI側で維持します。日本語への変更で、英語音声の理解度を音量判断へ持ち込まない構成にしました。

同じデジタル音声・係数でも、Web用機器とMRI提示系の耳元音量は一致しません。MRI内では本番の再生経路と装着状態で確認します。物理的な音圧・音声開始・撮像パルス同期は今回のソフトウェア検証の範囲外です。

## 保守と検証

HTML/JavaScriptのみで動作し、外部ライブラリやビルドは不要です。GitHub Pagesはmainブランチのルートを公開します。

```sh
node --test tests/*.test.mjs
python3 -m http.server 8766 --bind 127.0.0.1
```

研究プロジェクト内でのみ使う準備・照合コマンド：

```sh
PYTHONDONTWRITEBYTECODE=1 ../.venv/bin/python tools/prepare.py
PYTHONDONTWRITEBYTECODE=1 ../.venv/bin/python tests/compare_mri.py
PYTHONDONTWRITEBYTECODE=1 ../.venv/bin/python ../Experiment/tests/test_practice_materials.py
```

`prepare.py` は既存WAVを照合し、提供得点と課題別選定を8フォームに反映します。本番の刺激表・設定・固定予定は変更しません。検証結果は [verification.json](verification.json)、過去の検証はそのprevious_verificationを参照してください。実機Trainer・研究室PC・MRI/932を組み合わせた確認は別途必要です。
